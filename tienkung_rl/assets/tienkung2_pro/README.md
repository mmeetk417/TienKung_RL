# TienKung 2 Pro MuJoCo asset

This directory contains the committed, reproducible MuJoCo runtime asset for
the fixed-base `reach_then_close` task.  Normal installation and runtime model
loading use the committed MJCF and do not invoke the converter.

## Ownership and edit policy

The only hand-maintained inputs are:

- `configs/reach_then_close.yaml` (physics, materials, actuator gains and object contact);
- `source/tiangong2.0_pro_with_hands.urdf`, `source/meshes/*.STL`,
  `source/LICENSE`, `source/NOTICE`, and `source/README.md`;
- `patches/asset_patch.yaml`, `patches/collisions.yaml`,
  `patches/contact_groups.yaml`, `patches/sites.yaml`, `patches/scene.yaml`,
  and `patches/schema.json`.

The source files are immutable copies.  Replace them as an attributable set;
do not make local semantic edits.  The following files are generated and must
never be edited by hand:

- `source/source_manifest.json`;
- `mjcf/tienkung2_pro.base.xml`;
- `mjcf/reach_then_close.xml` and `mjcf/reach_then_close.viewer.xml`;
- `mjcf/name_index.json` and `mjcf/joint_hierarchy.json`;
- `manifest.json`.

The base MJCF is the normalized output of MuJoCo's real URDF importer.  The
pipeline first builds the full `reach_then_close.viewer.xml`: it keeps the 63
source STL visuals, retains the right-hand palm and twelve finger STL geoms as
physical mesh collisions.  The
right arm continues to use calibrated sphere/capsule/box primitives.  It then
derives `reach_then_close.xml` by deleting visual-only mesh declarations; the
headless runtime compiles the thirteen physical hand meshes and the
primitive arm/task geoms.

The scene patch also carries the checkerboard floor from
`rmm-sim/mj_assets/stanford_tidybot2/scene.xml` (MuJoCo's builtin `groundplane`
texture).  The floor is rendered in group 1 with collisions disabled, so this
appearance migration does not add a new training contact.

This split is deliberate.  MuJoCo loads dense STL inputs before its
`discardvisual` compiler pass, so that flag alone does not make one independent
model small enough for the 128-environment CPU baseline.  The viewer path keeps
the complete source appearance while the headless path compiles only declared
physical hand meshes, avoiding the other visual meshes.
Both files have independent descriptive SHA-256 values in `manifest.json`;
loading them does not require a configured checksum. Runtime and viewer use
the same physical settings.

## Regenerate and check

Use the locked Python 3.11 environment with MuJoCo 3.11.0 from the repository
root:

```bash
/home/mmeetk/miniconda3/envs/ft300/bin/python \
  -m tienkung_rl.assets.pipeline --generate

/home/mmeetk/miniconda3/envs/ft300/bin/python \
  -m tienkung_rl.assets.pipeline --check
```

`--generate` replaces generated outputs only.  `--check` regenerates into a
temporary directory and compares every generated byte without writing to the
committed asset tree.  Missing meshes, case-mismatched URDF references,
unknown patch targets, duplicate names, and conflicting writes fail closed.

After regeneration, run:

```bash
/home/mmeetk/miniconda3/envs/ft300/bin/python -m pytest -q tests/test_asset_pipeline.py
```

## Version upgrades

Changing MuJoCo or any import option requires an explicit tool-version update,
two clean deterministic generations, review of the base-MJCF golden hash, and
the full asset/simulation regression suite.  Raise the asset contract version
when a change affects joint/body/site/geom/actuator names or ordering, mimic
semantics, collision/contact groups, scene structure, reset posture, or a
consumer-visible hash.  Calibration-only changes must raise their M01 physics
or actuator calibration version and retain measurement evidence.

`manifest.json` records source, patch, tool, and output hashes.  Runtime and
checkpoint code should consume the manifest/name index rather than hard-code
MuJoCo integer IDs.

## Right-hand equality calibration v2

`right_hand_mimic_equality_v2` uses MuJoCo direct-format equality
`solref = [-10000000, -20000]`.  The previous v1 values
`[-1000000, -2000]` allowed a 0.023036988432 rad source-mimic residual during
the loaded open-hand hold, above the fixed 0.01 rad acceptance limit.  The v2
candidate was selected without changing the 0.005 s physics step, source joint
limits, actuator force limits, or the acceptance threshold.

The measurement is the real-MuJoCo regression in
`tests/test_asset_pipeline.py`: linearly command each active hand joint for
0.8 s, hold for 1.0 s under the committed scene contacts, and compare all six
right-hand follower joints to the source-URDF mimic equations.  MuJoCo 3.11.0
produced:

| close fraction | maximum mimic residual (rad) | maximum active target error (rad) | maximum joint-limit residual (rad) | warnings |
|---:|---:|---:|---:|---:|
| 0.0 | 0.005676724530 | 0.008109135447 | 0.000000000000 | 0 |
| 0.5 | 0.001002131186 | 0.004064225833 | 0.000000000000 | 0 |
| 1.0 | 0.000139606189 | 0.001970370697 | 0.001975370697 | 0 |

The final column counts MuJoCo warning categories with a nonzero occurrence.
The regression rejects any mimic or active-target error at or above 0.01 rad,
any non-finite state, and any warning.  The actuator control endpoints remain
the source- and follower-limit-safe ranges recorded in the runtime MJCF; the
small full-close position residual is MuJoCo's compliant joint-limit response
and remains below the same 0.01 rad tracking tolerance.

M03 remeasures the current collision/actuator v2 runtime with the object
isolated for hand-motion validation.  Its open/half/full maximum mimic
residuals are `0.00076625`, `0.00016443`, and `0.00035812` rad respectively;
these are historical measurements; the asset remains marked `starting_point_unvalidated`.
